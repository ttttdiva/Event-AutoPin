# フィルター・入力・マップと欠席編集

## フィルター

購入状態は複数選択でき、選んだ状態のいずれかに一致するサークルを表示する。未選択は全状態。「全て」は購入状態の選択と「見送り非表示」を解除する。他の検索・場所条件は維持する。「フィルター解除」は検索、場所、購入状態、優先度、ジャンル、おしながき有無、見送り非表示をすべて解除する。並べ替えは維持する。

有効条件はヘッダーを閉じていても表示する。一覧・マップに同じ `filteredCircles` を渡し、ジャンルも含めて条件を揃える。マップの優先度ボタンも一覧と共通の状態を更新する。マップは座標を持つサークルだけを対象にし、選択中のマップと未割当マップのピンを表示する。未購入が0件でも、状態の絞り込みを指定していなければ購入済み・買えなかった・見送りのピンを表示する。

## キーボード

Expo SDK 54対応の `react-native-keyboard-controller` を導入。ルートの `KeyboardProvider`、`KeyboardLayout.tsx` の `InputScrollView` / `InputModal` を共通で使う。FlatListは `renderScrollComponent` で自動スクロールを追加し、商品の編集中に行をクリップしない。

対象は商品名・価格・メモ、商品追加、サークル追加・編集、イベント作成・編集・メモ、イベント検索、クロール入力、設定入力、Xポスト再処理。今後入力UIを追加する場合も、スクロールするフォームを `InputScrollView`、入力モーダルを `InputModal` と組み合わせる。native依存の追加なので、旧APKやExpo Goだけでは確認できず再ビルドが必要。

## マップの選択表示

選択マスを白枠で強調する。ポップアップは地図の変形領域の外に置き、同じReanimatedのscale/translate値から毎フレーム画面座標を計算する。実測したポップアップサイズを使い、マスの上・下・左右から重なりの少ない位置を選び、画面内へ収める。ピン自体が画面外に移った間はポップアップを隠し、戻ると再表示する。

## デスクトップの欠席

サークル行を展開した詳細の「参加状況」で欠席を編集する。一覧にも「欠席」表示を付ける。既存の `absence_status` を使用し、欠席はモバイルと同じ `absent`、解除は `null` で保存する。旧データの `欠席` も欠席として表示し、未編集時には元の値を維持する。購入状態とは独立した情報であり、端末間の反映には既存のデータ転送・インポートを使用する。

## 検証

自動テストは購入状態の全15組み合わせ、全件購入完了、複合条件、ヘッダーの展開・解除・再選択、405種類の画面端・倍率・画面サイズでの配置、パン・ピンチ時の座標、欠席のJSON保存・解除を対象とする。

実機接続後に次を確認する。これらのnative UI確認は、自動テストやビルド成功だけでは完了扱いにしない。

1. 一覧の下部にある商品価格を編集し、数値IMEの表示中に商品名・別商品の価格へ移っても入力欄が見えること。
2. サークル編集フォームの末尾、イベント作成・編集・メモ、再処理URL、設定、クロール、検索で、IMEの切替・閉じ直し・複数行入力を確認する。
3. キーボード表示中も保存・キャンセルが操作でき、閉じた後にスクロール領域が正常に戻ること。
4. 一覧・分割・マップで複数状態と場所・ジャンルを組み合わせ、解除時も件数とピンの対象が一致すること。
5. 画面中央と四隅のピンを選択し、連続ピンチ・パン・ダブルタップ、一覧との分割切替でも対象とポップアップがずれないこと。
6. モバイル→デスクトップで欠席を読み込み、デスクトップで設定・解除・再読込してからモバイルへ戻し、状態が保持されること。

今回の実機確認は、ユーザーの端末接続後に行う。

WindowsのCMake/Ninjaはパス長制限があるため、Expo prebuildの互換性pluginでC++中間生成先をドライブ直下の `.ec/<checkoutのハッシュ>` へ短縮する。ビルドスクリプトは失敗したGradleの終了コードを呼び出し元へ返す。
