# 投稿本文・複数画像の同時おしながき解析

## 既定の処理

Pythonの通常クロール（twscrape）とURL指定再処理は、候補投稿の本文、添付画像全枚、対象イベント名・開催日・追加コンテキストを同じAPIリクエストに含める。画像付き投稿を本文だけの「予告」判定で打ち切らない。本文だけの投稿も同じ分類・抽出・検証を使う。

既定モデルはテキスト用・画像用ともにOpenAI `gpt-5.6-luna` / `max`。投稿の同時解析には画像側の設定を使い、失敗時は既存の画像APIフォールバック `gpt-5.6-sol` / `medium` を使う。テキストのみの既存機能のCodexフォールバックは変更していない。

画像の送信前リサイズ・合成・再エンコードは行わず、元画像を個別の `input_image` として本文と同時に送信する。OpenAI画像入力には `detail=high` を指定する。MIMEは拡張子でなく画像の実体から判定する。投稿あたりの元画像合計は32 MiBまでとし、超過時は一部の画像を省略せずエラーにする。

## 検証と更新境界

正常な応答は1回で確定する。不正JSON、画像番号の不整合、価格と根拠表記の不一致、重複商品の価格矛盾、モデルの要再確認判定があった場合だけ、同じ本文・全画像を用いて一度再確認する。未解決なら設定済みの次のAPIで再試行する。既定では最大4リクエスト（主モデル2回＋フォールバック2回）であり、従来の多段画像検証を毎回すべてLuna maxで回す設計ではない。API接続エラーは同一モデルで検証再試行せず次のAPIへ進む。SDK自体の通信再試行は別に存在する。

価格の未記載は `price=0` / `price_basis=not_shown`、明記された無料は `price=0` / `price_basis=free_explicit` として区別する。金額を推測しない。本文の明示的な無料への訂正も、旧価格が正の値だからという理由で無視しない。整数の円表記、共通価格、全角数字、カンマ、万円・千円表記の整合性を検証する。

各商品の `catalog_evidence` に、根拠の画像番号・保存画像名、本文の原文引用、価格表記、価格の根拠画像番号（0は本文）、元投稿URL、使用モデルを保持する。モデルが任意の画像パスや購入状態を指定することはできない。単品・セットは `sale_kind` で区別する。同一商品の画像間重複は統合し、異なる商品の価格を混同しない。

全画像を一時ディレクトリへ取得してから解析する。1枚でも取得できない場合、取得できた画像だけで成功にはしない。全検証が成功してから画像と商品を反映する。商品更新は選択した確定投稿の一覧で置き換え、同一商品名・種別の購入状態は保持する。旧一覧にしかない商品を無条件に足し戻して、削除・訂正を打ち消すことはしない。

取得・解析・期限切れの失敗では既存商品・メモ・画像参照を保持する。通常クロールの失敗では既読投稿IDも元に戻す。画像ファイル名は内容のハッシュを含むため、同一URLの画像が更新されても以前の画像を上書きしない。複数画像のファイル公開途中に障害が起きると未参照ファイルが残る場合はあるが、既存の参照先は削除しない。

未確定の「予告」は既存商品を消さない。通常クロールでは他の候補投稿の確定版を優先する。別投稿の画像に最初の候補の本文を組み合わせない。直接再処理のキャッシュは投稿IDだけでなくイベント・開催日・追加コンテキストで分離し、キャッシュ利用時も対象サークルの購入状態を優先する。共有の期限切れ後はキャッシュも更新しない。

## 互換性と対象外

明示的にCLIを含む画像モデル設定は従来経路を維持する。保存済みのCLI選択を勝手に書き換えない。同時解析を使う既存設定では画像側をAPIのみの設定に変更する。`skip_catalog_image_analysis` を指定した処理も従来経路を維持する。画像ファイル単独の既存解析API、Grok検索経路、モバイル独自のクロール実装は今回変更していない。

本文による候補投稿の収集・優先順位付けは既存処理を使う。すべてのX投稿を無条件に画像解析する変更ではない。一般的な小文字の誤読や実際の精度向上を、形式検証だけで保証するものでもない。

## 回帰テスト

```sh
python -m pytest tests/unit/test_catalog_post_joint.py -q
cd desktop-app
npm run test:runtime
```

Pythonの新規テストはAPI・Xをモックし、送信する本文・全画像・reasoning設定、価格根拠、重複、イベント不一致、キャッシュ、購入状態、取得失敗、遅延応答と期限切れを検証する。デスクトップのruntimeテストには同時解析の進捗表示と別runのログ混入防止を含める。新規の実行時モジュールとテストは公開同期マニフェストにも含める。

実APIを使ったおしながきの正解データとの精度比較や、Windows/Android実機での動作確認はこれらのオフラインテストには含まれない。
