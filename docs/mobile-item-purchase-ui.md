# 頒布物の価格固定・購入状態のタップ切替と長押しメニュー

## 表示と操作

`CircleExpandedDetail` の閲覧行は `ItemPurchaseRow` に分離している。
商品名は幅を制限した横スクロール領域に置き、価格と購入状態ボタンはその外に置く。
分類と他イベントでの購入済みバッジは次の行に表示し、商品名・価格の横幅を消費しない。
価格は桁区切り付きで表示する。0 は `0円`、null は `価格不明` と区別する。
商品名の全文は削除・省略せず保持し、左右へのスワイプで読める。通常タップで編集、長押しで削除する既存操作は維持する。

右端には `ItemPurchaseStatusMenu` のトリガーを1つだけ置く。円の外観は従来と同じ28dpで、タップ領域は44dp。
通常タップではサークルと同じ順序で「見送り → 未購入 → 購入済み → 買えなかった → 見送り」と1段階だけ切り替える。
長押しでは状態を変更せず、従来の選択メニューを開く。長押しを離したときに通常タップを重ねて発火させない。
ボタンは現在の状態アイコンを表示し、プルダウン矢印は表示しない。読み上げのヒントには次の状態と長押し操作を含める。
クロール・登録直後の初期値と、既存データの状態は変更しない。
メニューの選択肢は高さ56dp以上で、「購入済み」「買えなかった」「見送り」を文字付きで表示する。
選択済みの場合のみ「未購入に戻す」を追加する。同じ状態を再選択しても状態を反転させない。
保存値は従来通り0/1/2/3で、DBスキーマ・集計・エクスポートは変更しない。

メニューは右端に揃えて開き、画面下端に近い場合は上へ開く。安全領域を除く画面内に配置し、
大きな文字や低い画面で全体が入らない場合はメニュー内部を縦スクロールする。
外側タップ、Androidの戻る操作は保存せず閉じる。連打による二重保存を防ぎ、更新エラーは通知する。

## 自動検証

通常の `shopping-app` の `npm test` に `lib/item-purchase-ui.test.ts` を登録している。
画面幅240〜768、画面高さ240〜852、安全領域、画面端、長いメニューを組み合わせた5,832件の配置検査と、
実コンポーネントを読み込むモックによる構造・イベント契約検証を実施する。
後者はネイティブビューのレイアウトや実タッチイベントを検証するものではない。

```sh
cd shopping-app
npm ci --legacy-peer-deps
npm run typecheck
npm test
```

## Androidでの確認項目

1. 長い商品名と長い分類を登録し、価格が状態ボタンに重ならないことを確認する。名前だけ横へスワイプし、価格が動かないこと、スワイプ終了時に編集が開かないことも確認する。
2. 通常文字サイズと拡大文字サイズで、3つの状態、現在の選択表示、未購入への取消を確認する。0円と価格不明も確認する。
3. 画面上端・下端、分割画面、回転後にメニューが画面内に収まることを確認する。文字拡大で全体が入らない場合、内部スクロールで全選択肢に到達できることを確認する。
4. 各状態から通常タップで次の状態へ進み、4回で元に戻ることを確認する。長押しとその指を離す操作では状態が進まず、メニューだけが開くことを確認する。
5. 編集、長押し削除、並び替え、他イベントの購入済みバッジを確認する。メニュー外タップ、Androidの戻る操作、保存中の連打で意図しない編集・変更が発生しないことを確認する。
6. 保存した状態が再展開・アプリ再起動後も残り、購入金額の集計にも反映されることを確認する。

APKのビルド・公開・更新メタデータは `docs/release-checklist.md` と既存のビルドスクリプトに従う。
ソース更新やモックテストの成功を、実機確認・APK公開完了として扱わない。
